# 컨벤션

## 코드와 설계

- Google Java Style을 기준으로 합니다. 클래스는 PascalCase, 메서드·변수는 camelCase, 상수는 UPPER_SNAKE_CASE, DB 식별자는 snake_case, Enum 값은 UPPER_SNAKE_CASE로 작성합니다.
- 코드 식별자는 영어로 작성합니다. 주석은 필요한 경우에만 간결한 한글로 작성합니다.
- API 경로는 소문자 복수형 리소스를 사용하고 기본 경로는 `/api/v1`입니다.
- Controller는 HTTP 입출력만 담당하고, Service는 비즈니스 흐름과 트랜잭션을 담당하며, Repository는 DB 접근을 담당합니다. DTO와 DB 표현을 분리합니다.
- SOLID 원칙을 따르되 쉬운 설계를 우선합니다. 클래스는 한 가지 명확한 책임을 갖고 의존 방향을 분명히 합니다. 실제 요구나 중복이 확인되기 전에는 인터페이스, 추상 계층, 디자인 패턴을 추가하지 않습니다.
- 공통 추상화는 실제 중복이 확인된 뒤 도입합니다. 도메인 명칭은 `stock`으로 통일합니다.
- 재고 변경은 `stocks`와 `stock_movements`의 정합성을 지키며, 비즈니스 불변식을 임의로 완화하지 않습니다.

## 오류 처리

공통 예외 처리는 첫 API 구현 시 필요한 오류 코드, 도메인 예외, 전역 처리기만 추가합니다. 전역 처리기는 상태 코드와 `code`, `message`를 담은 JSON 응답을 반환합니다. 도메인 예외는 `RuntimeException`을 상속하고 메시지와 원인을 보존해 트랜잭션 롤백을 막지 않습니다. 참고한 saleday의 단순한 책임 분리를 유지하되, 서블릿 응답을 직접 조작하는 대신 DTO 응답을 사용하고 HTTP 상태는 이 프로젝트의 요구사항을 따릅니다.

## 테스트

- JUnit 5를 사용하며, DB 동작 검증은 PostgreSQL Testcontainers로 수행합니다. H2는 사용하지 않습니다.
- Spring Framework 7의 `SpringExtension`은 JUnit 6 이상을 요구하므로 `@SpringBootTest` 대신 테스트에서 Spring 애플리케이션을 직접 시작하고 종료합니다. JUnit BOM 5.14.4로 버전을 고정합니다.
- 동시성, 트랜잭션 롤백, 현재고와 movement 합계를 핵심 통합 테스트로 검증합니다.
- 테스트 이름은 검증할 동작과 조건이 드러나게 작성합니다. 실패하는 테스트를 삭제하거나 무시해 통과시키지 않습니다.

## Git과 커밋

- 브랜치는 `main`과 공통 작업 브랜치 `feature`만 사용합니다. 제품이나 기능별로 이름을 덧붙인 브랜치를 만들지 않습니다.
- 커밋 제목은 `feature: 한글 변경 요약`으로 통일합니다. 접두사는 `feature` 하나만 사용하며 괄호 안 scope는 붙이지 않습니다.
- 한 커밋에는 하나의 논리적 변경만 담습니다. 서로 독립적으로 리뷰할 수 있는 변경은 커밋을 나눕니다.
- 작업 하나의 구현·검증을 마치면 커밋·푸시하고, 다음 작업은 사용자와 검토한 뒤 진행합니다. 여러 작업을 끝까지 모아 일괄 커밋·푸시하지 않습니다.
- 제목 다음에는 빈 줄을 두고, 중요한 변경점과 이유를 본문에 항목별로 적습니다. 실제 변경 내용만 기록합니다.

  ```text
  feature: 프로젝트 실행 기반 구성

  - Java 21과 Spring Boot 4.1.3 기반 단일 모듈 구성
  - Gradle Wrapper 및 애플리케이션 시작점 추가
  - 로컬 설정과 에이전트 작업 파일의 Git 제외 규칙 추가
  ```

- 사용자가 변경을 리뷰하고 승인한 뒤에만 staging과 commit을 합니다. push는 별도 명시 승인이 있어야 합니다.
- `git add .` 또는 `git add -A`를 습관적으로 사용하지 않습니다. 상태와 staged diff, 비밀값·생성 파일 포함 여부를 확인합니다.
- force push, `reset --hard`, 기존 공개 이력 재작성, 승인 없는 tag 생성을 금지합니다.

## Markdown과 로컬 작업 파일

- README와 `docs/`의 설계·컨벤션·워크플로·결정 기록은 팀 협업을 위한 문서로 Git에 포함합니다.
- 루트 `AGENTS.md`와 `docs/TASKS.md`는 로컬 작업용이며 Git에서 제외합니다. 개인 메모나 로컬 설정을 프로젝트 문서에 섞지 않습니다.
- 문서에는 검증된 사실과 미구현 계획을 구분해 씁니다.
